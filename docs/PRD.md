# 鸢叙 PRD：完整体验与进度可靠性

版本：v0.2 · 2026-10-03。适用站点：https://ai-novel-w2x5.onrender.com/ 。

## 1. 产品定位与本次目标

鸢叙是以选择和自由输入驱动的 AI 互动小说。玩家循环为：理解处境与目标 → 选择行动 → 阅读后果与状态变化 → 决定下一步 → 达成结局 → 导出或回溯探索。

本次优先保证故事进度可信、试玩入口简洁、结束状态清晰，便于首次玩家和招聘方完整体验。它仍是 AI 叙事产品，状态变化由模型提出、程序校验并限制幅度；暂不宣称已具备确定性的战斗、经济或胜负判定系统。

## 2. 优先级及交付边界

| 优先级 | 问题 | 本次规则及交付 |
| --- | --- | --- |
| P0 | 失败、半截响应被保存为剧情 | 只有完整响应通过校验才写入玩家行动、正文、状态和回合；错误单独显示；允许重试同一行动 |
| P0 | 连续点击、离页、切换故事导致异步污染 | 请求期间锁定行动；离页取消；写入前校验会话身份；辅助请求结束后再开放下一回合 |
| P0 | 同名故事、同回合存档混淆 | 故事身份和当前分支身份采用独立 UUID；按存档身份恢复，不再依据回合数猜测 |
| P0 | 回溯只回正文，保留未来状态 | 每个成功回合保存完整状态快照；回溯先保存原分支，再创建新分支；后续自动存档只写新分支 |
| P0 | 存档缺正文和上下文、容量满静默删除 | 保存完整可用正文、选项、世界节点、副线、文风、摘要、线索、关系、记忆和结局；容量或配额不足明确提示，不自动删旧档 |
| P1 | 配置过长，登录阻断试玩 | 首页选择题材后可直接体验；不依赖登录成功；保留自定义入口，高级设定折叠 |
| P1 | 等待无反馈，选项失败后无路可走 | 区分生成正文和准备选项；支持停止等待；选项失败保留正文，可单独重试或自由输入 |
| P1 | 分章后清空消息导致刷新重开 | 摘要生成不清空历史；只有零回合且无正文才自动生成开场 |
| P1 | 结局之后仍能继续生成 | 结局持久化；隐藏行动区；提供导出全文、回溯分支、开始新故事 |
| P1 | 登录页暗示永久保存 | 明示本机浏览器存储，登录暂无云同步；支持导出 JSON 备份和 TXT 正文 |
| P2 | 小屏选题拥挤、阅读时被拉回底部 | 小屏两列，大屏三列；阅读旧内容时暂停自动跟随，提供回到最新 |

## 3. 首次体验

1. 首页选择八种题材之一（随机按钮只帮助选题材）。
2. 选择“快速体验”：使用本地预设世界与角色，无需先调用 AI 生成设定。每种题材有具体目标和现场困境。体验篇约 8 回合、1 章，模型在第 5 回合铺垫、第 7 回合收尾、第 8 回合被要求给出结局。该回合数为叙事引导，不保证模型严格遵循。
3. 或选择“自定义世界与角色”：必填字段不能只有空格；剧情节点、目标结局和文风默认折叠。随机生成失败保留原输入。
4. 开新故事前保存当前故事；保存失败则阻止切换，提示处理存储问题。新故事清空旧故事的线索、关系、摘要、记忆与风格，不污染新局。

## 4. 回合状态与错误恢复

状态：等待行动 → 生成正文 → 完整校验 → 提交回合 → 准备选项/辅助信息 → 等待行动或已完结。

- 正文生成服务端超时 90 秒，客户端 95 秒；选项 20 秒，摘要/关系/记忆 15 秒。超时不是成功回合。
- 正文单次尝试上限 40 秒；对暂时性失败、截断或格式异常自动重试一次。认证、额度错误及主动取消不重试。重试状态可见，只有完整结果推进一次回合。
- 流协议为 NDJSON：preview 仅供预览，complete 携带校验后的结构化数据，error 不能进入正文。缺少 complete 的断流不推进。
- 玩家行动和叙述使用同一成功回合编号，从 1 开始；失败不消耗回合、不清除剧情提示、不覆盖可用选项。
- 每条状态增量必须为有限数值；仅题材允许的指标生效，单次增量限制在 -15 至 +15，最终值限制在指标范围。
- 正文成功后立即存档一次，选项/辅助信息完成后更新快照。辅助服务失败不撤销正文；选项失败明确给出继续路径。
- 停止等待若发生在正文已提交后，只停止尚未完成的辅助处理，已完成正文保留。

## 5. 存档与回溯

- v2 存档含稳定的 storyId 与当前分支 id、创建/更新时间、完整可用正文及各回合快照。另存为生成独立存档 id。
- 快照保存该回合的消息数量、状态、选项、世界及节点、副线、文风、线索、关系、记忆、摘要和结局。回溯按消息数量截取，避免旧回合编号差异导致串段。
- 已有分支再次回溯也创建新的子分支；原档完整保留。存档上限 20，达到上限允许更新原档，不允许静默淘汰。
- 旧存档可恢复已保存的摘要和最近正文，无法补回从未保存的数据；旧数据没有历史快照的节点禁止回溯，新成功回合开始建立快照。
- 存档只属于当前浏览器、当前站点来源。换设备、换域名、清理站点数据不会自动迁移。JSON 备份用于保全完整数据，本次未提供导入界面；TXT 用于阅读与分享。
- “最近存档”按更新时间降序展示。配额不足时显示保存失败，不能显示成功提示。
- 自动保存失败时，游戏页提供“导出当前进度备份”，直接导出内存中的完整数据，不依赖已写入的旧存档。

## 6. 结局及可读性

结局类型仍为 good/bad/true/secret，由模型在结构化响应中提供，程序校验类型与标题。存档恢复后保留完结状态，普通行动与快捷键不能绕过。结局不强制把某个通用数值解释为成功或失败，后续再建设各题材独立规则。

玩家上滚阅读时停止自动滚动；返回底部或点击“回到最新”恢复跟随。生成中显示正文预览，不显示原始 JSON。

## 7. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| HTTP 失败、断流、无效 JSON、状态格式错误 | 回合/正文/状态/存档不变，错误可见，可重试 |
| 同一行动连续点击 | 至多一个请求提交一个成功回合 |
| 切换故事后旧请求晚到 | 不写入新故事 |
| 正文成功而选项失败 | 正文已保存，回合只增加一次，重试选项不增加回合 |
| 相同题材、同名世界、同回合的两个故事 | 独立保存，读取不串正文或辅助数据 |
| 回溯后继续并刷新 | 使用历史状态，新分支独立存档，原分支正文不变 |
| 到章节边界后刷新 | 历史保留，不再次生成开场 |
| 结局后读取存档、键盘操作 | 仍然完结，不新增回合 |
| 第 21 个存档或浏览器配额不足 | 明确提示，不删除原存档 |
| 全新浏览器、认证不可用 | 仍可快速体验，登录不作为游戏前置条件 |
| 手机窄屏、上滚阅读 | 题材卡片可读，旧内容不被自动滚动打断 |

自动化验证使用模拟模型响应，不消耗真实接口额度；上线验收还需以真实 DeepSeek 配置体验开场、选项和结局质量。

## 8. 后续迭代，不在本次代码交付中

- Render 冷启动：属于部署方案与套餐决策，界面调整不能消除首次服务器唤醒等待。
- 云存档及备份导入：需要账户归属、数据库策略、冲突处理与导入校验，单独设计。
- 明确的风险/收益预告、可验证的题材胜负条件、经济与战斗规则：先选一个题材做闭环，避免把模型生成数值直接包装成成熟规则系统。
- 玩法效果验证：关注开场到达率、首个行动完成率、选项失败率、故事完结率；本版本不虚构已有指标，也不新增外部数据采集。
